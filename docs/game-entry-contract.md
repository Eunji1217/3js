# 게임 입장 계약 (v3)

> 로비와 게임이 만나는 **유일한** 지점 (CLAUDE.md 불변식 1). 게임 담당자는 이 문서만 읽고 게임을 붙일 수 있어야 한다 — 로비 코드를 읽을 필요가 생기면 이 문서가 모자란 것이다.
> 바꿀 때는 PROGRESS 결정 기록에 근거와 함께 적고, 버전을 올리고, 이미 붙은 게임 담당자에게 알린다.

## 한 줄 요약

로비는 **게임 URL 로 페이지를 이동**하면서 `hub_return` 쿼리에 복귀 URL 을, `hub_name` 쿼리에 플레이어 이름을, `hub_room` 쿼리에 로비 방 코드를 붙인다. 게임은 끝나면 **복귀 URL 로 그대로 이동**한다. 이름·방은 써도 되고 무시해도 된다. 그 외에 둘이 주고받는 것은 없다.

## 흐름

```
로비 (문 앞에서 입장)
  └─ location.assign("<게임 URL>?hub_return=<복귀 URL, 인코딩됨>&hub_name=<이름, 인코딩됨>&hub_room=<방 코드>")
        게임 페이지 (자기 스택·자기 서버·자기 입력 처리, 이름·방은 원하면 씀)
          └─ 끝나면 location.assign(<hub_return 값 그대로>)
로비 (다시 로드 → 서버 재접속 → 들어갔던 문 앞에 등장)
```

## 게임이 지켜야 할 것 (MUST)

1. **브라우저에서 URL 하나로 열린다.** 그 URL 이 게임의 시작 화면이다. 스택·번들러·프레임워크·렌더러는 자유.
2. **`hub_return` 을 읽어 두었다가, 게임을 나갈 때 그 값으로 이동한다.** 게임 안에서 페이지를 옮겨 다녀도 이 값은 끝까지 유지해야 한다.
   ```js
   const back = new URLSearchParams(location.search).get('hub_return');
   // 「로비로」 버튼, 게임 종료 시 등
   if (back) location.assign(back);
   ```
3. **복귀 URL 은 불투명한 값으로 다룬다.** 해석하거나 고치거나 쿼리를 덧붙이지 않는다. 로비가 그 안에 무엇을 넣을지는 로비 사정이고, 언제든 바뀔 수 있다.
4. **로비를 import 하지 않는다.** 로비의 코드·에셋·서버 프로토콜에 의존하지 않는다. 다른 게임도 마찬가지.

## 게임이 해도 되는 것 (MAY)

- **`hub_name` 을 플레이어 이름으로 쓴다** (v2). 이름 칸을 미리 채우거나 그대로 표시한다. 단:
  - **표시용 힌트일 뿐이다.** 로그인이 없어 누구나 주소창에서 바꿀 수 있다 — 사람을 구별하거나 권한을 주는 데 쓰지 않는다.
  - 화면에 넣을 때는 **텍스트로만** (`textContent` 등). `innerHTML` 에 그대로 넣지 않는다.
  - 아래 「로비가 지키는 것」의 길이·문자 규칙도 믿지 않는다 — 게임 서버로 보낸다면 서버에서 다시 검사한다.
  - 없거나 비어 있으면 게임의 기본 동작(이름 입력 등)으로 간다 — 게임 단독 실행, v1 로비.
  ```js
  const name = new URLSearchParams(location.search).get('hub_name')?.trim() || null;
  ```
- **`hub_room` 을 자기 서버의 방 이름으로 쓴다** (v3). 같은 로비 방에서 온 사람끼리 게임에서도 같은 방에 모이게 된다. 단:
  - **비밀이 아니다.** 로비의 초대 링크에 그대로 보이는 값이고 주소창에서 바꿀 수 있다 — 방 이름으로만 쓰고 입장 권한·신원 확인에 쓰지 않는다.
  - 아래 형식 규칙을 믿지 않는다 — 게임 서버로 보낸다면 서버에서 다시 검사한다 (길이·허용 문자).
  - 없거나 비어 있으면 게임의 기본 동작(방 만들기·기본 방 등)으로 간다 — 게임 단독 실행, v1·v2 로비.
  - 게임 서버는 로비 서버와 별개다 — 같은 코드를 쓸 뿐 방 명단을 공유하지 않는다.
  ```js
  const room = new URLSearchParams(location.search).get('hub_room') || null;
  ```
- 게임 URL 에 **자기 쿼리·해시**를 둔다. 로비는 등록된 URL 의 기존 쿼리를 보존하고 `hub_` 파라미터만 추가한다. `hub_` 접두어는 로비 몫으로 예약 — 게임 쪽 파라미터에 쓰지 않는다.
- 게임 안에서 **다른 URL 로 이동**한다 (게임 내 페이지 전환). 이때 `hub_return` 을 직접 들고 다녀야 한다 — `sessionStorage` 에 저장해 두는 것을 권한다.
- **`hub_return` 이 없을 때** (게임 단독 실행·개발 중) 「로비로」 버튼을 숨기거나 아무 동작도 하지 않는다. 게임은 로비 없이도 열려야 한다.
- 안전을 위해 복귀 URL 이 `http:` / `https:` 로 시작하지 않으면 무시한다 (`javascript:` 등 차단). 그 이상의 검사는 하지 않는다 — 로비와 게임은 출처(origin)가 다를 수 있다.

## 로비가 지키는 것

- 등록된 게임 URL 을 **바꾸지 않고** 연다 — 기존 쿼리·해시 보존, `hub_` 파라미터 추가만.
- `hub_name` 은 1~16자, 제어 문자 없음, 앞뒤 공백 없음 — 로비 멀티 서버가 이름에 거는 규칙과 같다. 로비에서 정한 이름이 없으면 붙이지 않는다.
- `hub_room` 은 6자, 문자는 `23456789abcdefghjkmnpqrstuvwxyz` 중에서 (헷갈리는 0·o·1·l·i 를 뺀 숫자+소문자). 로비 방에 들어가 있지 않으면 붙이지 않는다.
- 붙이는 순서는 `hub_return` → `hub_name` → `hub_room` 이지만 게임은 순서에 기대지 않는다.
- `hub_return` 은 항상 **절대 URL** (`http:`/`https:`) 이다.
- 게임에 **아무것도 요구하지 않는다** — 크기·스택·입력·iframe·SDK 없음 (불변식 2).
- 브라우저 **뒤로 가기**로 돌아와도, `hub_return` 으로 돌아와도 정상 동작한다 — 둘 다 들어갔던 문 앞에 선다. 로비는 언제든 처음부터 다시 로드될 수 있다고 가정한다.
- 입장 시 로비의 멀티플레이 접속은 페이지 이동과 함께 끊기고, 복귀 시 다시 접속한다.

## v3 에 없는 것

- **결과 전달** (점수·승패를 로비로 돌려주기) — 없음.
- **이름·방 밖의 플레이어 정보** (ID·외형·같이 들어간 사람 명단) — 없음. 로비 서버의 접속 번호는 게임 서버에게 의미가 없다. 게임 안 멀티플레이는 게임이 알아서.
- **로비 안에서 게임 띄우기** (iframe·모듈 mount) — 하지 않는다. 이유는 PROGRESS 결정 기록 2026-10-09 「게임 입장 계약」.

필요해지면 `hub_` 파라미터를 더하는 식으로 다음 버전을 연다 (이전 버전 게임은 모르는 파라미터를 무시하면 그대로 동작).

## 게임 등록

게임 담당자가 로비 담당에게 넘기는 정보는 아래 세 가지뿐이다. 로비는 이것을 등록 표 한 곳(`lobby/src/data/games.ts`)에 적는다.

| 항목 | 예 | 설명 |
|------|-----|------|
| `id` | `snake-race` | 영문 소문자·숫자·`-`. 저장소 안이라면 `games/<id>/` 폴더 이름과 같게 |
| `title` | 스네이크 레이스 | 로비에서 문 앞에 보일 이름 |
| `url` | `/games/snake-race/` 또는 `https://example.com/game/` | 게임 시작 URL. 상대 경로(로비와 같은 호스트) 또는 절대 URL |

어느 문에 연결할지는 로비가 정한다.

### 게임이 어디에 있든 된다

- **이 저장소의 워크스페이스** `games/<id>/` — 루트 `typecheck`/`build` 가 `--if-present` 로 돈다. 해당 스크립트가 없으면 그냥 건너뛴다.
- **이 저장소의 단순 폴더** — 빌드 없는 정적 HTML 이라도 된다.
- **외부 URL** — 다른 저장소·다른 호스트. 계약은 URL 뿐이라 그대로 붙는다.

배포·호스팅 위치는 아직 정하지 않았다 (PROGRESS 열린 질문 5). 개발 중에는 게임 자기 dev 서버 URL 을 등록해도 된다.

## 붙이기 전 자가 점검

- [ ] `<게임 URL>?hub_return=https%3A%2F%2Fexample.com%2F` 로 열었을 때 게임이 정상 시작된다
- [ ] 게임을 나가면 `https://example.com/` 로 이동한다 (값을 바꾸지 않고)
- [ ] `hub_return` 없이 열어도 게임이 깨지지 않는다
- [ ] (이름을 쓴다면) `&hub_name=%3Cb%3E%EC%B2%A0%EC%88%98%3C%2Fb%3E` 로 열면 `<b>철수</b>` 가 굵은 글씨가 아니라 글자 그대로 보이고, `hub_name` 없이 열면 기본 동작으로 간다
- [ ] (방을 쓴다면) 두 창을 `&hub_room=abc234` 로 열면 같은 방에, `hub_room` 없이 열면 기본 동작으로 간다. `&hub_room=..%2F..` 처럼 이상한 값도 게임 서버가 거른다
- [ ] 게임 URL 에 자기 쿼리가 있으면 `<게임 URL>&hub_return=...` 로도 정상 동작한다
- [ ] 게임 코드가 `lobby/` 나 다른 `games/*` 를 import 하지 않는다
